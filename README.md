```text
HTML
CSS

Accessible Navigation
Client-Side Validation
```

## Backend

The contact system uses **Supabase** for storing website messages.

The current architecture includes:

```text
Visitor
   ↓
Contact Form
   ↓
Supabase Data API
   ↓
public.messages
   ↓
Protected Admin Dashboard
```

The website uses a **publishable Supabase key** on the frontend.

### Security

Sensitive Supabase secret/service-role keys must **never** be placed inside:

* HTML files
* CSS files
* JavaScript files
* GitHub repositories
* Client-side source code
* README files

Database access is controlled with **Row Level Security (RLS)** and authenticated admin access.

# 📨 Contact System

The contact page allows visitors to submit:

```text
Name
Email
Message
Created Date / Time
```

Submitted messages are stored in the Supabase table:

```text
public.messages
```

The administrative dashboard can authenticate the authorized admin account and retrieve/delete messages according to the configured database policies.

Visitors should **never** submit passwords, API secrets, private keys, or other sensitive credentials through the public contact form.

---

# 🔐 Admin Dashboard

The project includes:

```text
admin.html
```

The admin area is separate from the public website and uses Supabase authentication.

The public website should not expose administrative credentials or Supabase secret keys.

The `robots.txt` file also requests search crawlers not to crawl:

```text
/admin.html
```

This crawler instruction is not a security boundary. Authentication and database access policies provide the actual protection.
